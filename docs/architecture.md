# Архитектура: принципы разделения ответственности

Короткий документ о том, **почему** код разделён именно так. Если новое поведение не влезает ни в один из пунктов — сначала придумать, куда оно падает по этим принципам, и только потом писать.

## 1. Один модуль — одна причина изменения

| Модуль | Отвечает за | Причина измениться |
|---|---|---|
| `main.ts` | сборка: плагин (onload/onunload), настройки, подписка на событие окна, склейка семантических событий трекера с доменом и пикером | новый шаг в цепочке «свайп → пикер → перенос» |
| `touch-claim.ts` | механика claim'а: распознать правый свайп раньше жестов Obsidian, глотать события клеймнутого жеста, порог, отмена drawer'а | правила распознавания/глотания/безопасности жеста |
| `paragraph-transport.ts` | домен: найти абзац под координатой, перенести его в другую заметку | правила переноса (что и куда переносится) |
| `swipe-cut.ts` | визуальный эффект: вырезание, слот, светящаяся пластина | внешний вид и поведение эффекта (декорация) |
| `note-picker-modal.ts` | UI выбора целевой заметки | только UI пикера |
| `editor-position.ts` | координаты экрана → позиция редактора (парк стратегий) | появление/замена стратегии позиционирования |
| `settings.ts` | окно настроек (императивное + декларативное для Obsidian 1.13+) | форма настроек |
| `lib/*` | чистые функции и структурные пробники (см. ниже) | алгоритмы/пробники |

Правило: два изменения разного рода (например, «новый шаг пайплайна» и «новый вид эффекта») никогда не должны попадать в один файл.

## 2. Направление зависимостей — в одну сторону

```
main.ts → touch-claim, paragraph-transport, swipe-cut, settings → lib/*
```

- `lib/*` (gesture, paragraph, coords, notes-search, runtime-probe) **не импортируют ничего из Obsidian** — они чистые и тестируемые в изоляции. Исключение: `lib/notify.ts` — его единственная работа это показ Notice.
- Никто не импортирует `main.ts` обратно.
- Модули общаются **семантическими событиями и типами-результатами** (`onTravel`, `onAccepted`, `ParagraphLookup`, `SwipeCut | null`), а не сырым DOM-состоянием.

## 3. Границы знаний

- `touch-claim` знает про жесты, но не знает про пикер, эффект и абзацы.
- `paragraph-transport` знает про заметки и абзацы, но не знает про жесты и UI.
- `swipe-cut` знает про DOM и стили, но не знает про заметки. Эффект — декорация: любой его сбой не ломает пайплайн жеста (только отключает сам эффект на текущем жесте).
- `main.ts` — «дерижёр», и именно в нём лежит состояние, связывающее модули (`SwipeSession`: какой абзац резолвился и жив ли эффект). Это его единственная логика.

## 4. Недокументированные API Obsidian — только через `lib/runtime-probe.ts`

Все обращения к членам, которых нет в типах (`editor.cm`, `leftSplit`, `getEditable`…), идут через `isObject` / `readObject` / `readFunction` / `readNumber` / `readElement` / `safely`. Сырые проверки `typeof x === "object"` и касты в клиентском коде запрещены — только guard'ы: проверка и сужение типа в одном месте.

## 5. Логи

В плагине нет логов: `console.*` нет нигде; отладочного режима нет. Пользователь видит только **итоговые** сообщения: результат переноса и ошибки операции, когда она действительно не удалась (`lib/notify.ts`, `showError`).

## 6. Сущности

- Функция без нескольких вызовов и без самостоятельного смысла не создаётся: «разделение без принципа разделения — плохо».
- Экспортируется только то, что нужно другим модулям: внутренние константы и helpers не экспортируются.
- Одноразовые переменные инлайнятся, если это не ухудшает чтение.
